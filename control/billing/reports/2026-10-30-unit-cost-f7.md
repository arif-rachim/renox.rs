# Unit cost per request, F7 fields — 2026-10-30

The unit-cost report of #325: the same arithmetic as `2026-10-28-unit-cost.md`, now with the F5 to F7 meter fields (`meter.md` 0.2 to 0.4) and the PDF conversion in the billed CPU. Produced by `control/billing/src/unit-cost.ts`.

**Hardware.** This machine (Intel Core i7-6700 @ 3.40 GHz, 8 threads), git `177aef4` (batch F67-B), a `renox-worker` release build, and the Bun 1.4.4 load generator on the same machine. This is not `node-small`, so the numbers are relative, not a benchmark result.

**Method.**
- `bench/lib/worker.sh setup/start` with `examples/shop` as `shop.localhost`, and the 100 seeded products (`POST /api/dev/seed`).
- 1,000 warm-up requests, then 10,000 measured requests from a closed-loop Bun client at concurrency 1 (`load.ts`, kept with the session).
- The mix: 30 % `GET /products` (page), 30 % `GET /products/:id` (page), 20 % `GET /api/products?q=dates`, 20 % `GET /api/products/:id`.
- The report reads every record of the run: the seed, the warm-up and the measured requests.

**Cost inputs.** The hypotheses of `docs/01-business.md`: one node at $125/month, 4 vCPU, 60 % of its CPU sellable, egress at $0.09/GB. AI tokens are left unpriced, because `docs/01` has no provider price.

## Findings

- **Pages cost more than the API.** Two of the four request kinds are pages now (render pool and templates), so billed CPU per request is 0.696 ms mean and 2.156 ms p99. On 2026-10-28 it was 0.360 ms for an API-only mix. Cost per 1M requests is $0.13, against $0.82 then: page responses are smaller than the product JSON that dominated egress then.
- **The process uses more CPU than it bills.** The worker process used 20.55 s of CPU (`/proc/<pid>/stat`, user plus system) for the 11,001 requests, which is 1.87 ms each. The bill counts 0.696 ms. The rest is gateway, HTTP and render-pool overhead that no tenant is billed for. It is the platform's cost per request and belongs in the price (`docs/01-business.md`, "Unit economics").
- **None of the F5 to F7 fields fired.** This load signs no one in, opens no realtime connection, and calls no storage, AI or PDF op, so every new field is 0 and no record carries one. Those dimensions get their numbers from:
  - the products' own loads (#337);
  - B14 (realtime) and B18 (failover) on `node-small` (#158);
  - a priced `--ai-usd-mtok` once the AI gateway has a provider contract (#327).
