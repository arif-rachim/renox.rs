## Findings

- **Path B costs the tenant more CPU than path A costs in total.** At 100 items path B's isolate time is 1.48 ms, against path A's 0.70 ms isolate plus 0.26 ms render. Rendering in V8 costs more than marshaling the data and rendering in Rust. At 1,000 items: 10.84 ms against 4.03 + 2.40 ms. On the free tier's 50 ms CPU limit, that is headroom the tenant's own code loses, and with one isolate per deployment it is time no other request of the deployment can run.
- **"Path B wins on very large data sets" (`docs/08-template-engine.md`) did not hold at 1,000 items.** Marshaling 1,000 cards costs less than rendering them in JavaScript. Larger pages were not measured. A 253 KB page is already past what an htmx page should send.
- **Under load, path B makes the CPU-accounting finding #155 much worse.** With 8 concurrent connections every request of either path stays far below 50 ms of its own CPU, yet the meter ends requests with `cpu_limit`. Path A loses 51 of about 1,200 page requests; path B nearly every request (about 700 out of 700, roughly 1–2 succeed per second). Each termination ends every request in flight on the isolate (#156), and path B's longer isolate occupancy makes the cascade continuous. This is the same spurious `RENOX_CPU_LIMIT` as #155, reproduced on a pages workload. The `error` (500) records are the collateral requests in flight on a terminated isolate. Reported on #155.
- **Path A's fragment costs more than its page.** At 1,000 items the render pool spends 3.88 ms on the `product_list` fragment and 2.40 ms on the whole page. A fragment request evaluates the whole page and then renders the block (`Renderer::render_to`, the finding from #45). Path B renders the block alone, so at 100 items its fragment p50 is lower than path A's (2.45 against 2.85 ms) while its CPU is the same. This is an argument for fixing path A's fragment rendering, not for path B.
- **The cell adds to every page it renders:** the CSP nonce on `<script>`, and in `<head>` the `renox-request-id` and `renox-deployment` meta tags and the client script (#126). A function response has none of them. This is why `b_page_*_bytes` is 299 bytes shorter than `a_page_*_bytes`. If path B ever becomes a page mode, the cell has to apply the same additions to its output.
