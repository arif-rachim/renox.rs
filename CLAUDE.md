## Releases

Release commits go straight to `main` with their tag: no branch, no PR (this exception is for release bumps only). Run from a clean `main` that equals `origin/main`; each command shows the diff and asks y/N before it commits, tags and pushes. `--dry-run` shows the change and reverts it; `--yes` skips the prompt; `--skip-tests` skips the local tests (typecheck still runs). On Windows the local tests are skipped (a CRLF checkout fails the cli tests on `main` too), and CI runs them after the push.

**Start with the wizard: `bun run bump-version`** (`--dry-run` first, to see the state and what it recommends). It reads what changed since `worker-v*` (in `crates/`, `Cargo.*`) and since `cli-v*` (in `cli/`, `sdk/`), a worker release that the CLI does not pin yet, a version on `main` without its tag, and a worker CI run still going. It then offers worker + CLI, worker only, CLI only, pin, or tag, with the recommendation first. It drafts the CHANGELOG notes from the commits (use, edit in the git editor, or abort), asks the version (patch, minor, major, or one you type), confirms the plan once, and runs it. Worker + CLI waits for `release-worker.yml` (about 80 minutes). If the wait breaks, running `bun run bump-version` again goes on from the released worker. `--yes` takes the recommendation, patch versions and the drafted notes.

The steps it runs. They are not `package.json` scripts: run one directly only for a special case the wizard does not offer, such as pinning the same worker version again (`--dry-run` works there too):

1. `bun scripts/release/bump-worker.ts <patch|minor|major|x.y.z>`: `crates/renox-cell` version (Cargo.toml and Cargo.lock), then the tag `worker-v<v>`, which runs `release-worker.yml`.
2. When that run is green: `bun scripts/release/pin-worker.ts [x.y.z]`. It writes the release's sha256 (`SHA256SUMS`, plus `SHA256SUMS.unpacked` for the pdf variant) into `PINNED_WORKER` (`cli/src/worker/verify.ts`), moves `WORKER_VERSION` and the docs, and adds a CHANGELOG line. It pushes to `main` with no tag.
3. Write the notes under `## <v> (unreleased)` in `CHANGELOG.md`, push them, then run `bun scripts/release/bump-cli.ts <patch|minor|major|x.y.z>`. It moves the CLI, create-renox and `@renoxium/sdk` together (they share the tag `cli-v<v>`, which runs `release-cli.yml` and `release-sdk.yml`), updates the install lines, `bun.lock` and `llms-full.txt`, and dates the CHANGELOG entry. `bun scripts/release/bump-cli.ts --tag-only [x.y.z]` only tags a release commit that is already on `main`.

The scripts live in `scripts/release/`, with tests in `bun test scripts/release`.
