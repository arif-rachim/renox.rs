What your app gets

Its own isolate
CPU, memory, wall-clock and network limits are enforced in Rust, so a runaway loop in one app never slows another.
Its own database
One SQLite file per tenant, backed up continuously. Every statement a module runs passes the SQLite authorizer.
Pages rendered on the server
HTML templates rendered in Rust, htmx fragments, View Transitions, SSE and WebSockets. No SPA unless you want one.
Modules instead of rewrites
Sign-in with 2FA and phone OTP, organizations and roles, billing, tax invoices, admin, storage, email and WhatsApp. Change a module's page without forking it.
Access rules in one place
Cedar policies for roles, attributes and relations, route guards, and queries scoped to the signed-in user.
Deploys you can undo
Every deploy is an immutable artifact. Promote, roll back, read logs and usage per app in the dashboard.

From a folder to a live app

pages/products/[id].html is the page at /products/:id, and the loader beside it reads the data.

  1. Create the app from a template: bunx renox new my-shop
  2. Run it on the real runtime: bunx renox dev
  3. Add sign-in with its tables, pages and policies: bunx renox add auth
  4. Deploy to my-shop.renoxium.app: bunx renox deploy
