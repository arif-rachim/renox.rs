pages/products/[id].ts

import type { LoaderContext } from "renox";

export const guard = { action: "product.read" };

export async function load({ params, db }: LoaderContext) {
  const product = await db.queryOne(
    "select * from shop__products where id = ?", [params.id]);
  if (!product) return new Response(null, { status: 404 });
  return { product, inStock: product.stock > 0 };
}

Folders are routes. Configuration is the exception.

  1. Write pages and functions

    pages/products/[id].html is /products/:id. A loader next to it fetches the data; the template renders it in Rust.

  2. Install modules

    renox add auth brings sign-in with 2FA, its tables, pages and policies. Override a template without forking the module.

  3. Deploy and watch

    Every deploy is an immutable artifact. Promote, roll back, read logs and usage per app in the dashboard.

What you get

An isolate per tenant

CPU, memory, wall-clock and network limits are enforced in Rust. A runaway loop in one app never slows another.

SQLite per tenant

One database file per tenant, with continuous backups. Module tables are prefixed and every statement passes the SQLite authorizer.

Modules are the product

Auth with 2FA and phone OTP, organizations and roles, billing, tax invoices, admin, storage, email and WhatsApp.

HTML first

Server-rendered pages with htmx fragments, View Transitions, SSE and WebSockets. No SPA unless you want one.

Authorization built in

Cedar policies for roles, attributes and relations, route guards, and queries scoped to the signed-in user.

Usage-based, idle is free

An idle app is evicted from memory and costs almost nothing. You pay for requests, CPU and storage you actually use.
